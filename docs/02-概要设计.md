# 概要设计

## 架构

系统采用前后端分离架构：

- 前端：Vue 3 + Vite + Element Plus，提供智能检索、作业指引、知识管理三页。
- 后端：FastAPI，提供 REST API、静态前端托管和上传文件访问。
- 数据：`data/search.db` 保存手册和案例全文索引；`data/app.db` 保存案例、标注和图谱元数据。

## 关键模块

- `services/search_store.py`：SQLite FTS5 检索，结合领域词、中文 n-gram 和 LIKE 兜底提高召回。
- `services/rag.py`：组织检索证据、风险等级、引用和建议动作；mock 模式下输出基于证据的离线答案。
- `services/llm.py`：统一 mock/local/api 三种大模型调用，DeepSeek API Key 由 `.env` 注入。
- `services/workflow.py`：根据检修等级和故障关键词生成标准作业执行单。
- `services/knowledge.py`：案例审核后写入检索索引，并生成设备、部件、故障、方案关系。
- `services/uploads.py`：统一图片上传校验和保存，限制 JPG/PNG/WebP 与最大体积。

## 数据流

1. 维修手册通过 `scripts/ingest_pdf.py` 抽取文本并写入 `search.db`。
2. 用户提交问题后，后端按设备型号和关键词检索手册/案例片段。
3. RAG 模块生成离线答案，或调用 DeepSeek/API 模型生成答案。
4. 用户提交反馈后写入 `annotations`。
5. 新案例审核通过后，同时写入 FTS 索引和知识图谱。

## 安全设计

- `.env` 不提交，API Key 预留为空。
- 上传图片使用 MIME 白名单、扩展名白名单和大小限制。
- LLM prompt 截断，降低 token 和网络开销。
- 前端展示相对图片 URL，不暴露后端文件系统路径作为业务入口。
