# 设备检修知识检索与作业系统需求分析

## 目标

面向一线检修人员、班组长和知识管理员，建设一个 B/S 架构的设备检修助手，解决维修手册分散、检索慢、作业流程不一致、经验难沉淀的问题。

## 用户角色

- 检修人员：输入故障描述、设备型号或现场图片，获取手册片段、诊断建议和作业步骤。
- 班组长：审核一线案例，确认关键步骤和安全合规项。
- 知识管理员：维护案例、人工标注和知识图谱。

## 功能需求

1. 多模态知识检索：支持文本、设备型号、图片描述联合检索，返回手册页码、案例来源和相似度。
2. RAG 智能问答：支持 mock、本地模型、DeepSeek/OpenAI 兼容 API 三种模式；答案必须带引用依据。
3. 标准化作业指引：按设备型号、检修等级、故障线索生成步骤、工具、安全项、检查点和完成进度。
4. 知识沉淀：支持案例上传、图片附件、审核入库、写入检索索引、更新知识图谱。
5. 人工标注：支持对模型输出评分和修正，保留引用来源，为后续优化提供数据。

## 非功能需求

- 稳定性：无 API Key 时仍可用离线检索和规则化诊断。
- 安全性：上传文件限制类型和大小；API Key 不写入代码仓库。
- 易用性：首屏即工作台，检索证据、风险等级、进度状态清晰可见。
- 低资源开销：核心检索使用 SQLite FTS5，不引入向量库或大型常驻服务。
